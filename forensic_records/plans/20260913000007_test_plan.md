# Test Plan: Financial Guard Fail-Closed Patch (20260913000007)

## Objetivo
Garantir que a falha de contenção (timeout de lock) no `enforce_financial_guard` sele a multa como zero, preservando a integridade forense mas protegendo contra overbilling, e validar que o true-up (`reconcile_financial_guard`) respeita o teto financeiro em vez de canonizar erros passados.

## Casos de Teste (pgTAP)
1. **`test_hold_financial_guard_lock_exists`**: Garante que a função auxiliar test-only foi criada e revogada do PUBLIC.
2. **`test_enforce_financial_guard_fail_closed`**: (Testado primariamente via Dart integration test devido à concorrência, mas verificaremos a estrutura da trigger aqui se possível).
3. **`test_reconcile_financial_guard_clamp`**: Insere multas que forçariam o overbilling histórico, invoca o `reconcile_financial_guard`, e garante que o `accrued_cents` seja clampado ao `monthly_penalty_cap_cents`.
4. **`test_reconcile_financial_guard_audit_log`**: Garante que o clamp gere um registro `FINANCIAL_GUARD_DRIFT` com `overshoot_clamped = true`.

## Assertivas
- `original_fine_cents` deve conter o valor original.
- `cap_month_utc` deve estar presente no payload para eventos fail-closed.
- Reconciliação não deve ultrapassar o limite.
