# Test Plan: 20260821000003_fix_forensic_evidence_snapshot.sql

**Governing Migration:** `20260821000003_fix_forensic_evidence_snapshot.sql`
**Invariants Checked:** INV-9, INV-26, INV-22

## Purpose
Ensures that the `verify_forensic_evidence` and `verify_forensic_evidence_by_queue` RPCs return the full canonical row encoded as JSONB inside the `snapshot` key, preventing TOCTOU vulnerabilities where the application had to perform a separate non-verified query.

## Scenarios
1. **Verification by Ledger Entry ID**
   - Condition: A valid `ledger_entry_id` is queried for an organization.
   - Expected Output: The `snapshot` property in the returned JSON must contain top-level fields such as `organization_id`, `ledger_entry_id`, `sealed_at_utc`, and `integrity_hash`, not just the inner rule evidence JSON.

2. **Verification by Queue Entry ID**
   - Condition: A valid `queue_entry_id` is queried.
   - Expected Output: The same shape as scenario 1.

3. **Tamper Check (INV-9)**
   - Condition: The RPC evaluates an evidence row where the `integrity_hash` does not match the computed hash of the inner `snapshot` field.
   - Expected Output: The `status` field must evaluate to `tampered`.

4. **Error Parity (INV-26)**
   - Condition: Cross-tenant lookup or non-existent ID.
   - Expected Output: Must raise `P0002` exception with a sanitized message.
